# ChatGPT Plus Price Monitor

监控 [priceai.cc](https://priceai.cc/products/chatgpt-plus) 上的 ChatGPT Plus 报价。
当**最低可信报价**达到设定阈值时，通过 Telegram 发送通知。

## 功能

- 按固定间隔轮询，并支持随机抖动
- 使用中位数识别主流价位，可选过滤异常低价
- 仅在价格状态变化时通知，避免重复推送
- 抓取连续失败时告警，恢复后自动通知
- 未配置 Telegram 时可作为命令行价格查询工具使用

## 快速开始

### 1. 构建

需要 Go 1.23 或更高版本。

```sh
make build
```

生成的可执行文件为 `chatgpt-plus-price-monitor`。也可以安装到系统：

```sh
make install
```

### 2. 查询当前价格

不设置 Telegram 环境变量时，程序只打印日志，不发送通知：

```sh
./chatgpt-plus-price-monitor -i 0 -v
```

根据查询结果选择合理的 `--threshold`，再启用通知。

### 3. 配置 Telegram 通知

```sh
export TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
export TELEGRAM_CHAT_ID=123456789

./chatgpt-plus-price-monitor -i 3m:1m -n 5 -t 10
```

> [!IMPORTANT]
> 不要将 Bot Token 写入命令行参数或提交到版本库。程序只从环境变量读取 Telegram 凭据。

## 配置

### 价格与轮询

- **`-t, --threshold`** · 默认 `10`
  最低可信报价小于或等于该价格（元）时通知。

- **`-i, --interval`** · 默认 `3m:1m`
  轮询基础间隔和最大抖动。`3m:1m` 表示每隔 3～4 分钟检查，`3m` 表示不使用抖动，`0` 表示只检查一次。

- **`-s, --sample`** · 默认 `30`
  用于计算参考价位的报价样本数。

- **`-f, --floor-ratio`** · 默认关闭
  启用地板线过滤。低于“参考价位 × 该比例”的报价将被剔除。

- **`-n, --top`** · 默认 `5`
  日志与通知中最多列出的低价报价数。

### 通知与网络

- **`--cooldown`** · 默认 `24h`
  价格持续低于阈值时的重复提醒间隔。设为 `0` 表示只提醒一次。

- **`--no-rebound`**
  价格回升到阈值以上时不发送通知。

- **`--fail-threshold`** · 默认 `3`
  连续抓取失败 N 次后告警。设为 `0` 表示关闭失败告警。

- **`--timeout`** · 默认 `30s`
  单次 HTTP 请求的超时时间。

- **`-v, --verbose`**
  打印每条报价的店铺和标题。

完整说明也可通过以下命令查看：

```sh
./chatgpt-plus-price-monitor --help
```

## 异常低价过滤

卖家有时会将加购项、拼车等不同规格放在同一商品下。这些价格可能只有正常价格的零头，直接使用最低价或均价容易产生误报。

程序通过以下步骤判断“真便宜”：

1. 获取由 `--sample` 指定数量的报价。
2. 使用样本**中位数**作为参考价位，避免极端值影响。
3. 设置 `--floor-ratio` 后，计算“地板线 = 参考价位 × 比例”。
4. 剔除低于地板线的报价，再将最低可信报价与 `--threshold` 比较。

例如，阈值为 `10`，参考价位为 `11`，地板线比例为 `0.5`：

| 报价样本 | 过滤结果 | 判断结果 |
| :--- | :--- | :--- |
| `2, 11, 11.5, 12, 11` | `2` 被剔除，最低可信报价为 `11` | 不通知 |
| `9, 11, 11.5, 12, 11` | 无报价被剔除，最低可信报价为 `9` | 通知 |

默认不启用异常低价过滤，所有报价都会参与判断。需要过滤明显低于主流价位的加购项或拼车报价时，可以显式设置比例：

```sh
./chatgpt-plus-price-monitor -i 0 -v --floor-ratio 0.5
```

> [!TIP]
> `--sample` 应明显大于 `--top`。样本过少时，如果低价报价恰好都是不同规格，中位数本身也会失真。比例越小，过滤越宽松；比例越大，过滤越严格。

## 通知策略

程序仅在状态变化或冷却时间结束时推送：

| 场景 | 行为 |
| :--- | :--- |
| 最低可信报价从阈值以上降到阈值以内 | 发送“降价提醒” |
| 价格持续处于阈值以内 | 保持静默；超过 `--cooldown` 后再次提醒 |
| 最低可信报价回升到阈值以上 | 发送“价格回升”；使用 `--no-rebound` 可关闭 |
| 连续抓取失败达到 `--fail-threshold` | 发送“监控异常”，附带原始错误 |
| 抓取从异常恢复 | 发送“监控已恢复” |

同一轮抓取故障只告警一次。如果告警发送失败，程序不会将其记为已发送，下一轮会继续尝试。

> [!NOTE]
> 去重状态仅保存在内存中。程序重启后会重新开始判断；如果此时价格仍在阈值以内，将再次发送降价提醒。
